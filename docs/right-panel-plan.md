# Правая панель Nest — план переработки

Статус: запланировано, код не изменён. Осмотр 26.11.2026: Nest 0.1.3 / исходники `b57cfb1`, Orca 1.4.277, Windows. Сценарии — в [продукте](product.md#54-ревью-изменений), границы реализации — в [архитектуре](architecture.md#722-правая-панель--целевое-решение-adr-011).

## 1. Что не работает как надо

Сравнил открытые настольные окна. В Orca в состоянии чистой ветки видны компактная полоса иконок, текущая ветка и upstream, `Up to date`, фильтр `All changes`, `Open diff`, `Graph`, поиск, меню и `Commit`. Пустое состояние объясняет **и** отсутствие локальных правок, **и** отсутствие коммитов впереди upstream. В Nest на чистом `main checkout` видны шесть равноправных вкладок, недоступные сетевые кнопки, пустой список, форма коммита с отмеченным `Stage all changes` и пять последних коммитов. Окна показывали разные репозитории; это сравнение подачи, а не результатов Git. Грязное состояние Orca и содержимое её меню вживую не проверялись: ниже это требования к Nest, не утверждения о реализации Orca.

| Что видно в Nest | Где и почему | Что меняем |
|---|---|---|
| `Git` перечисляет файлы, но клик по имени не открывает патч; надо перейти в `Diff` и снова искать файл | [GitFileRow](../apps/desktop/src/renderer/src/components/GitPanel.tsx#L423-L469) — строка без навигации; [Diff](../apps/desktop/src/renderer/src/components/DiffPanel.tsx#L131-L167) загружает выбранный режим целиком | Клик/Enter открывает патч конкретного файла с нужной стороны. Список и патч используют один выбор |
| Частично staged файл показывается одной строкой с `Unstage`, а счётчик незастейдженных скрывает вторую сторону | [GitPanel](../apps/desktop/src/renderer/src/components/GitPanel.tsx#L238-L242) считает `total − staged`, хотя [status](../packages/core/src/git/status.ts#L60-L82) отдаёт оба статуса | Независимые секции и счётчики индекса и рабочего дерева |
| `Commit` по умолчанию захватывает все правки; первый коммит заблокирован, хотя core умеет его создавать | [Дефолты формы](../apps/desktop/src/renderer/src/components/GitPanel.tsx#L33-L42), [условие блокировки](../apps/desktop/src/renderer/src/components/GitPanel.tsx#L370-L395), [GitService.commit](../packages/core/src/services/git.ts#L188-L210) | Обычный `Commit` берёт только индекс; `Stage all` явно меняет индекс; запрет без `HEAD` относится к `Amend`, не к первому коммиту |
| Сбой чтения истории или веток может выглядеть как «Git status unavailable»; возможна перезапись свежего статуса старым ответом | [Общий Promise.all без проверки ревизии](../apps/desktop/src/renderer/src/components/GitPanel.tsx#L44-L83); [App запрашивает status отдельно](../apps/desktop/src/renderer/src/App.tsx#L307-L327) | Один снимок статуса на задачу, независимые загрузки, защита от поздних ответов |
| Шесть вкладок конкурируют за фиксированные 390 px; форма и история делят один скролл со списком | [RightPanel](../apps/desktop/src/renderer/src/components/RightPanel.tsx#L50-L75), [layout](../apps/desktop/src/renderer/src/styles.css#L165-L174), [прокрутка](../apps/desktop/src/renderer/src/styles.css#L1045-L1094) | Компактная навигация, закреплённые контекст и действия, отдельный скролл списка, resize и сворачивание |

Не заменяем рабочий Git-сервис с нуля: операции, режимы diff, история, сравнение, дерево, watcher и комментарии уже есть. [Текущий сквозной тест](../apps/desktop/e2e/workflow.spec.ts#L101) покрывает commit и первую публикацию на worktree; он не опровергает перечисленные пробелы UX и крайние случаи.

## 2. Целевая панель

```text
[ Files ] [ Source Control · 3 ] [ Sessions ]   [ Collapse ]
feature/login → origin/feature/login   ↑2      [ Push ] [ ⋯ ]
[ All changes ▾ ] [ Search ] [ Tree/List ]      [ Open diff ]
────────────────────────────────────────────────────────────
▾ Staged (1)                                [ Unstage all ]
  M  login.ts             +8 −2                        [ − ]
▾ Unstaged (1)                              [ Stage group ]
  M  login.ts             +1 −0                        [ + ]
▾ Untracked (1)
  ?  notes.md                                          [ + ]
────────────────────────────────────────────────────────────
[ Commit message                         ]    [ Commit ▾ ]
```

Текстовый эскиз показывает иерархию, а не размеры элементов; `⋯` открывает вторичные действия, включая `History` и `Compare`.

- **Верхняя полоса:** `Files` · `Source Control` · `Sessions` с иконками, подсказками, доступными названиями и видимым фокусом. `History` и `Compare` доступны из `Source Control` и палитры; `Open diff` — из панели. Не держим `Git`, `Diff`, `History`, `Compare` отдельными соседними вкладками верхнего уровня.
- **Контекст Git:** текущая ветка, upstream, ahead/behind и бейдж `Main checkout`; `Publish branch` при отсутствии upstream и наличии remote, `Push` при опережении, `Pull` при отставании (только fast-forward). При расхождении — `Fetch` и объяснение, без автослияния. Для отсутствующего remote, detached HEAD, ветки без коммитов или неизвестного tracking-статуса показываем причину недоступности, не `Up to date`. Статус upstream отражает известные локально refs; открытие панели не делает сетевой запрос.
- **Изменения:** `All changes` по умолчанию — секции `Staged`, `Unstaged` и `Untracked`, конфликты выделены отдельно. Поиск по имени и пути, tree/list, статусы, `old → new` и `+/-`, когда известны. Частично staged файл имеет две строки с разными патчами; общий счётчик файлов не суммирует дубликаты. Действия по файлу и секции не меняют выбранную сторону неявно. Сравнение `Against base` остаётся отдельным режимом: не выдаём его за локальный staging или трёхточечный `Compare`.
- **Ревью:** клик/Enter по строке сразу показывает её патч. `Open diff` даёт широкий просмотр с той же целью и навигацией назад к строке. В обычном окне он расширяет правую область, оставляя терминал видимым; в узком — открывается по запросу в drawer, закрытие возвращает фокус и не пересоздаёт PTY. Сохраняем inline/range-комментарии, «Outside this patch» и явную отправку в сессию. В `Files` остаётся read-only превью, не редактор.
- **Коммит:** компактный блок `Commit` доступен без прокрутки списка. По умолчанию только staged; черновик не пропадает при переключении задачи или неуспешном коммите. `Amend` — вторичное действие, только при существующем HEAD. Push отдельно; если не удался после коммита, показываем, что коммит сохранён локально; повторяем только push. `Discard` и `Force push with lease` — отдельные осознанные действия, не автоматические попытки восстановления.

Заимствуем у Orca иерархию, плотность и переход от списка к патчу, не фирменные стили. В первый выпуск не входят `Create PR`, проверки PR, граф со всеми ветками, встроенный редактор и staging по строкам. История из режима `History` заменяет `Graph` в первом выпуске; отдельный граф имеет смысл только после проверки спроса.

## 3. Порядок реализации

| Этап | Работа | Условие завершения |
|---|---|---|
| **P0.1 — исправить Git, до смены layout** | Общий снимок status и проверка ревизий; корректная проекция двух сторон Git; commit staged-only, отдельный Stage all, первый commit и unstage до первого коммита. Отдельные ошибки статуса/истории/операций. Проверить semantics `Discard` и явно назвать его область до подтверждения; не выдавать восстановление из `HEAD` за отмену только unstaged | Тесты на частично staged файл и первый коммит зелёные. Git-индекс не меняется от простого просмотра, а обычный commit не захватывает unstaged/untracked |
| **P0.2 — новая оболочка и ревью** | Три раздела, шапка ветки, изменение ширины и сворачивание, клавиатурная навигация; дерево/список и поиск; выбор файла и стороны, общий переход в широкий diff. Перенести входы в `History`/`Compare` и обновить палитру и e2e-селекторы по ролям | Файл открывается в один клик/Enter; можно вернуться к списку с выбором и фокусом. Терминал и заметки остаются доступны, переключение задач не смешивает контекст |
| **P0.3 — синхронизация и полировка** | Предсказуемые Publish/Push/Pull, причины недоступности и долгие операции с видимым состоянием. Явное подтверждение смены цели публикации, discard и force-with-lease; тесты с локальным bare remote. Windows-скриншоты узкого и обычного окна плюс чистого, грязного и конфликтного состояния | Сценарий «изменил → посмотрел → staged → commit → publish/push» проходит в обоих типах workspace. Ошибки не скрывают рабочую часть панели, не стирают изменения и не требуют повторного коммита |
| **P1 — после проверки P0** | При необходимости: side-by-side diff, граф веток, детализация больших деревьев/истории. Не усложнять P0 ради визуального паритета | Отдельный сценарий и критерий пользы перед реализацией |

## 4. Приёмка

- **Unit / интеграция:** статус двух сторон, конфликт не маскируется как staged, rename/copy, binary, удалённый и untracked файл, пути с пробелами/кириллицей; первый commit и unstage в unborn; ошибочный запрос истории не ломает `Changes`; поздний ответ до мутации или из A не затирает новый статус B; обновления watcher объединяются.
- **E2E, временные репозитории:** UI-коммит только индекса при частичном staging (содержимое проверить через Git), повтор после отказа push без второго коммита, первая публикация в bare remote, отсутствие remote/upstream, divergence и detached HEAD, конфликт, внешний stage/checkout, A → B → A с черновиком и выбранным файлом, комментарий к нужной стороне и отправка в FakeHarness. Не проводить разрушительные сценарии на пользовательском checkout.
- **Ручной Windows smoke:** на 1100×700 и широком окне, при системном масштабировании 100% и 150% — нет обрезанных названий действий или горизонтального скролла оболочки; длинные пути читаются по фокусу/подсказке; список скроллится без потери кнопок; Tab/стрелки/Enter/Esc работают, терминал не теряет ввод из-за watcher. Сравнить чистую и грязную панели с Orca на одинаковом репозитории до финальной полировки.
- **Гейт реализации:** `pnpm typecheck`, `pnpm lint`, `pnpm test`, целевые Windows E2E и скриншоты. Для этого документа перечисленные сценарии — план проверок, не отчёт о состоявшемся прогоне.
